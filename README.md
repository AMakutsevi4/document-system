# Documents

backend-сервис по работе c документами
---

## Поиск и фильтрация
Поиск документов реализован по периоду даты создания (createdAt).

---

## Инструкция по запуску

### 1. Запуск инфраструктуры

Клонируйте проект:
```
https://github.com/AMakutsevi4/document-system.git
```
Выполните команду:
```
docker-compose up -d
```
Из корневой папки проекта выполните сборку:
```
mvn clean package
```
### Запустите основной сервис:
```
java -jar document-service/target/document-service-1.0-SNAPSHOT.jar
```
При желании, укажите размер пачки документов(дефолтное значение - 500):
```
--service.batch-size=1000
```

### Запуск генератора документов:
```
java -Dfile.encoding=UTF-8 -jar document-generator/target/document-generator-1.0-SNAPSHOT.jar
```
По умолчанию установлены следующие значения:
```
--generator.size=1000 --generator.api-url=http://localhost:8080/api/v1/documents
```

Для корректного отображения логов, перед запуском введите команду:
```
chcp 65001
```

### 3. Архитектурные решения

#### Обработка 5000+ ID в одном запросе
В базовой реализации используется @Scheduled для фоновой обработки документов пакетами фиксированного размера, в соответствии с требованиями ТЗ.
Для обработки пакетов свыше 5000+ ID, лучше применить Apache Kafka. Основные преимущества:
- Мгновенный запуск;
- Оптимизация ресурсов;
- Надежность.

#### Вынос Реестра утверждений в отдельную систему
Для отделения реестра в отдельный микросервис, я бы применил паттерн Transactional Outbox, а именно в сервисе документов смена статуса на APPROVED
и запись в историю происходят в одной транзакции с сохранением события в специальную таблицу outbox в той же БД, и отдельным процессом пересылах их в Kafka,
где сервис реестра слушает и сохраняет запись в свою БД.
